# KEV Analysis (Phases 12-13)

KEV = Kev-4B decision model, used FROZEN and ZERO-SHOT as a routing gate. It answers four boolean
questions per knowledge item (relevant_xss, reusable, volatile, needs_verification) in one forward
pass; raw probabilities are stored and never treated as truth. Full route distribution over the
36-item corpus is in `reports/final/tables/kev_routes.json` (generated by `xss kev-route`).

## Observed routing behaviour (sample)
- Core XSS principles (e.g. "innerHTML parses HTML" k-008): relevant≈0.94, reusable≈0.86,
  volatile≈0.25 → **TRAINING_CANDIDATE**.
- Framework facts (React escaping k-020): relevant≈0.80, reusable≈0.83 → **TRAINING_CANDIDATE**.
- Volatile advisory meta-item (k-036): relevant≈0.33, volatile≈0.94 → **IGNORE / RAG_ONLY**
  (kept out of weights).

## Assessment
KEV separates stable, reusable XSS principles (→ training) from volatile/advisory material
(→ retrieval) with sensible zero-shot behaviour, supporting its use as a lightweight curator. It is
NOT a calibrated XSS relevance judge and is not the truth engine — verification (independent) decides
trust, and the promotion gate decides model acceptance. KEV is pinned by commit + adapter hash in
`provenance/kev.json`.
